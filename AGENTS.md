## Conventions

- **File naming**: `UiBank_<Action>.xaml` for reusable UI workflows in `UiBank/` (PascalCase action after prefix)
- **Argument naming**: `in_`/`out_` prefixes, e.g. `in_LoanAmount`, `out_LoanApproved`, `out_LoanId`, `out_LoanRate`
- **Root activity**: all authored workflows use a top-level `Sequence` (no Flowcharts/StateMachines except the recorded `monolith-main.xaml`)
- **Logging**: `ui:LogMessage` at start/end of each workflow and on each branch outcome, with `Level` set explicitly (`Trace`, `Info`, `Warn`)
- **Error handling**: soft-fail via `Warn`/`Trace` log messages on not-found conditions (e.g. "Logout button not found", "Loan id ... not found!") rather than throwing

## Key Workflows

| Workflow | Purpose | Services/Activities Used |
|----------|---------|--------------------------|
| UiBank_Login.xaml | Logs into UiBank using a stored credential asset (`in_CredentialsAssetName`, default `UiBank_Credentials`) | NClick, NTypeInto, NCheckState, LogMessage |
| UiBank_ApplyforLoan.xaml | Submits a loan application (email, amount, term, yearly income, age) and returns approval/id/rate | NTypeInto, NClick, NGetText, VerifyExecutionTypeIntoOptions, LogMessage |
| UiBank_CheckLoanDetails.xaml | Looks up a loan by `in_LoanId` and returns email/amount/rate/term/age/yearly income | NGetText, NCheckState, VerifyExecutionOptions, LogMessage |
| UiBank_Logout.xaml | Logs out of UiBank, tolerating a missing tab or missing logout button | NClick, NNavigateBrowser, VerifyExecutionOptions, LogMessage |
| monolith-main.xaml | Recorded end-to-end Flowchart across UiBank screens (Login, Loan Home, Apply, Details, Result, Accounts) in Chrome — unrefactored recording, not the process entry point | NApplicationCard, NClick, TargetAnchorable |

## Architecture

- **Pattern**: Modular UI-automation workflows intended to be orchestrated from `Main.xaml` (Login → ApplyForLoan → CheckLoanDetails → Logout implied by the file set), but `Main.xaml` is still an empty scaffold. `monolith-main.xaml` is a separate, unrefactored recorded Flowchart covering the same user journey.
- **Data flow**: Loan inputs (`in_email`, `in_LoanAmount`, `in_LoanTerm`, `in_YearlyIncome`, `in_Age`) → `UiBank_ApplyforLoan` → `out_LoanApproved`/`out_LoanId`/`out_LoanRate`; `out_LoanId` feeds `UiBank_CheckLoanDetails.in_LoanId` to verify persisted details against `TestData`.
- **External integrations**: UI Automation (Chrome) against the UiBank web application. Mail, Office 365, Excel, WebAPI, and Integration Service packages are declared as dependencies but not used in any sampled workflow.
